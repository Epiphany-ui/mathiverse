# Mathiverse AI 生成工作室与沉浸式 Sandbox 设计

## 状态

- 日期：2026-08-11
- 状态：已由用户确认，等待书面规格审阅
- 范围：Sandbox 视觉与交互、AI 生成编排、自动验证与渲染、自动修复、人工接管、多端适配和完整验收
- 关联设计：`2026-08-09-homepage-digital-math-gallery-design.md`、`2026-08-10-rag-manim-codegen-design.md`

## 背景

当前 Sandbox 已能通过 AI 生成 Manim 代码，也已经引入 DeepSeek V4 Pro、向量检索与专用修复能力，但体验仍有三个核心问题：

1. 用户提交后需要等待较长时间，期间缺少可信、持续的反馈，容易误以为页面卡死。
2. 生成结果没有经过完整的语法检查、兼容检查和真实渲染闭环，一次生成的成功率与可用性不稳定。
3. Sandbox 仍接近通用聊天工具和代码编辑器的组合，视觉上与首页「数字数学画廊」的数学语言不统一，也缺少进入创作空间的沉浸感。

本设计把 Sandbox 重构为一个“数学动画生成工作室”：允许高质量生成花费更长时间，但必须让用户看见真实进度；系统自动完成规划、检索、生成、验证、快速渲染和有限次数修复，同时永久保留手动渲染与手动 AI 修复。

## 目标

1. 提高首次生成后可成功渲染的概率，而不是单纯追求更快返回代码。
2. 在长耗时任务中持续提供真实阶段、已用时间和可取消能力，不显示虚假百分比。
3. 自动执行“生成 → 检查 → 快速渲染 → 最多两次修复”的闭环。
4. 保留代码编辑、手动渲染、手动 AI 修复、版本回退和人工接管。
5. 将 Sandbox 设计为与首页数字数学画廊和全局品牌和谐的沉浸式暗场。
6. 桌面、平板、手机和手机横屏均可完整操作，而不是仅缩放桌面布局。
7. 交付时全量测试、类型检查、代码检查和生产构建均为零错误，并通过真实运行验证。

## 非目标

- 不训练或微调新的基础模型。
- 不公开模型的原始思维链；只展示产品化的阶段摘要。
- 不建立通用分布式任务平台；初版沿用现有 Next.js 与渲染服务边界，仅增加清晰的生成作业协议。
- 不重构与 Sandbox 无关的社区、Wiki、Explore 或发布业务。
- 不用粒子、玻璃拟态、霓虹渐变和“AI 星光”作为主要视觉语言。
- 不在初版加入多人实时协作、复杂时间线编辑器或专业级节点编辑器。

## 已确认的核心决策

1. 采用质量优先的自动流水线，允许生成时间较长，但必须提供持续反馈。
2. 默认自动验证、自动快速渲染并最多自动修复两次。
3. 手动渲染和手动 AI 修复始终保留，不因自动流程而隐藏或删除。
4. 视觉方向采用 C「沉浸式暗场」，主画布是第一视觉主体。
5. 首次进入采用有仪式感的“场景开幕”动效，并为低性能设备和减少动态效果用户降级。
6. 初版保持概念模型的克制范围：聚焦生成成功率、过程反馈、工作台布局和可靠接管，不堆叠外围功能。
7. 多端适配与完整无报错是交付硬门槛，不接受“只有桌面可用”或“只有新增代码无报错”。

## 总体架构

系统分成两个对用户可理解、对实现可独立测试的单元。

### Generation Orchestrator

生成编排器负责：

- 识别新建、修改或修复任务。
- 生成简短、结构化的场景规划。
- 检索通过质量门槛的相关 Manim 示例。
- 调用合适的模型生成或修改代码。
- 执行语法、Manim API 与结构预检。
- 请求低清快速渲染。
- 在失败时携带完整错误上下文进行最多两次自动修复。
- 保存每个代码版本、验证结果、预览和最终状态。
- 通过结构化事件报告真实阶段。

编排器不负责界面布局，也不允许前端根据文本猜测任务是否成功。

### Studio Shell

生成工作室外壳负责：

- 展示任务输入、场景规划、阶段状态和已用时间。
- 管理主画布、对话任务栏、代码面板和版本历史。
- 消费生成事件并恢复当前任务视图。
- 提供取消、重试、手动渲染、手动 AI 修复、编辑和版本回退。
- 根据设备尺寸切换布局，不改变核心能力。

工作室只渲染编排器提供的明确状态，不伪造进度，也不解析模型的自然语言来推断阶段。

## AI 质量策略

### 1. 正确区分新建与编辑

- 全新 Sandbox 的默认示例代码只用于编辑器占位和教学，不自动作为用户任务的 `currentCode` 发送。
- 只有用户明确加载、生成或修改过代码时，任务才进入编辑模式。
- 当前代码在一次模型请求中只有一个权威来源，不同时重复出现在系统提示词、历史消息和当前消息中。

这避免新请求被默认圆形/方形示例锚定，也避免历史代码与当前编辑器内容冲突。

### 2. 分阶段模型路由

- 分类、提示词整理和简短场景规划优先使用快速模型或确定性逻辑。
- 复杂 Manim 代码生成与修复使用代码能力更强的模型。
- 简单参数修改、文案替换和颜色调整不必每次调用最重模型。
- 输出预算按任务复杂度动态选择，常规目标约为 4K--12K tokens，不默认放开到 32K。

模型的 `reasoning_content` 不直接传给用户。界面只展示“正在规划镜头”“正在检查 Manim 兼容性”等来自编排器的阶段说明。

### 3. 结构化场景规划

正式生成代码前先形成可解析的 Scene Plan，至少包含：

- 数学对象与关系。
- 场景布局与相机类型。
- 主要动画阶段与顺序。
- 需要持续更新的参数或追踪器。
- 预期时长和复杂度等级。

规划用于约束生成与修复，但不要求用户逐项确认。用户可在界面中展开查看简化版规划。

### 4. 经过质量门槛的 RAG

保留现有 pgvector 与 Ollama 检索，但增加以下约束：

- 设置相似度阈值；不相关时宁可不注入示例。
- 按二维/三维、数学领域、难度与 Manim 版本筛选。
- 只有通过 Python 编译、场景类检查和至少一次低清渲染的示例才可标记为可检索。
- 检索服务不可用时使用少量、经过验证的通用示例，不一次注入完整静态示例库。
- 检索超时必须可取消，不能在超时后继续占用后台资源。

本设计保留 `2026-08-10-rag-manim-codegen-design.md` 的数据库与语义检索方向，但以本设计的阈值、版本过滤、渲染认证和有限上下文规则为准。

### 5. 自动质量闭环

每次生成依次执行：

1. 提取并规范化完整 Python 代码。
2. Python 语法编译。
3. Scene 类、入口类和禁止模式检查。
4. 已知 Manim API 与版本兼容预检。
5. 低清快速渲染。
6. 成功后返回预览；失败则携带完整 traceback、当前计划和当前代码进入修复。
7. 自动修复最多两次。仍失败则停止自动循环，保留最后版本并交给用户手动处理。

修复接口优先返回完整可运行代码。若未来继续支持结构化 diff，diff 解析失败时不得无提示地串行消耗第二次完整模型调用；应明确转入一次受控的完整代码修复。

### 6. 渲染缓存

渲染缓存键由以下内容确定：

- 规范化代码。
- Manim 与 Python 运行环境版本。
- 渲染质量和画幅。
- 必要的资源摘要。

缓存键不包含当前时间。完全相同的代码与环境应复用验证和预览结果，减少重复等待。

## 生成作业与事件协议

### 作业状态

一个生成任务拥有稳定的 `jobId`，其状态只能沿以下状态机流转：

`queued → planning → retrieving → generating → validating → rendering → repairing → completed`

任意运行状态都可以进入 `cancelled` 或 `failed`。`repairing` 完成后可重新进入 `validating`，但自动修复次数上限为二。

初版由现有 Next.js 服务运行 AI 编排，Python FastAPI 服务只负责验证与渲染，不把模型调用复制到两个技术栈。作业元数据、代码版本、最后阶段和带序号事件写入现有 Supabase，由服务端执行受控写入；活动请求在 Next.js 进程中推进。登录用户按用户 ID 隔离，匿名 Sandbox 使用不可猜测的签名会话令牌隔离，客户端不能凭 `jobId` 读取其他任务。

这种边界允许页面刷新后恢复快照与事件，也符合当前本地渲染服务架构。它不承诺服务进程重启后自动续跑：进程重启时，持久化的运行中任务会转为 `failed`，并以 `failureReason: interrupted` 表示可从最后版本重试。

### 事件类型

前后端通过带递增事件编号的结构化事件通信：

- `accepted`：任务已创建并返回 `jobId`。
- `phase`：阶段开始或结束，包含可读摘要。
- `heartbeat`：任务仍存活，包含已用时间，不包含虚假百分比。
- `code_delta`：可选的代码流式更新，仅更新编辑器草稿。
- `version_saved`：新代码版本已保存。
- `validation`：语法/API 检查结果。
- `render`：快速预览开始、缓存命中、成功或失败。
- `repair`：自动修复次数与原因。
- `completed`：返回最终版本和预览。
- `failed`：返回用户可理解的错误、可重试动作和技术详情引用。
- `cancelled`：任务已停止，现有代码与版本仍保留。

断线重连时客户端携带 `jobId`、签名会话凭据与最后事件编号，只补发有权访问的缺失事件。若服务进程重启导致运行被中断，任务以 `failed` 和 `failureReason: interrupted` 持久化，保留最后代码和阶段，用户可以从该版本重新执行。

## 端到端用户流程

1. 用户从首页提示词或 Sandbox 输入进入工作室。
2. 工作室立即创建任务，展示场景规划阶段、已用时间、取消按钮和手动接管入口。
3. 规划完成后显示一行可读的场景摘要，并继续检索和生成，无需再次确认。
4. 代码生成时编辑器可显示草稿，但草稿不会被标记为可运行版本。
5. 验证与低清渲染成功后，主画布展示预览并标记最终可运行版本。
6. 自动修复发生时，界面显示“第 1/2 次修复”及简短原因，不播放夸张警报动画。
7. 完成后提供高清渲染、继续修改、手动 AI 修复、代码编辑、版本回退和发布入口。
8. 自动流程失败时，界面保留场景规划、最后代码、完整日志入口和所有人工操作，不出现空白结果页。

## 工作室视觉设计

### 视觉方向

Sandbox 采用「沉浸式暗场」，与首页暗色展厅共享视觉基因，但强调工具性：

- Gallery Black `#0B0F0C`：主背景和画布舞台。
- Archive Paper `#F2F3ED`：主要文字和关键浅色表面。
- Mathematical Ink `#121510`：浅色浮层中的正文。
- Function Blue `#4169FF`：函数、主要操作和当前阶段。
- Orbit Green `#25BEA5`：成功、轨迹和可运行版本。
- Calculus Orange `#FF603B`：修复、警示和关键参数。

中文继续使用 Noto Sans SC，界面与代码元数据使用 JetBrains Mono。层级依赖比例、细线、坐标和留白建立，不依赖大量圆角卡片、阴影、渐变光球或 sparkle 图标。

### 桌面布局

- 主画布占据最大面积，是进入页面后的第一视觉主体。
- 左侧为可折叠任务栏，包含提示词、场景规划、阶段轨道和简短对话。
- 底部代码面板可拖动高度并完全收起；生成期间默认只露出状态和当前文件信息。
- 顶部保留 Mathiverse 品牌入口、任务名称、连接状态和关键操作，但不形成厚重 SaaS 导航条。
- 版本历史以细线时间轴或编号序列呈现，不使用相同尺寸的卡片瀑布流。

### 状态视觉

- 空闲：画布显示低对比度坐标网格与创作提示。
- 生成：当前阶段节点、细线脉冲和已用时间提供反馈；非当前阶段保持安静。
- 渲染：主画布成为真实预览舞台，可展示渲染帧或低调的扫描线进度。
- 修复：使用 Calculus Orange 标记错误位置和修复次数，不将整个界面染成红色。
- 完成：Orbit Green 只标记可运行状态、预览边界或最终版本节点。
- 失败：保留画布、代码和历史，只在对应阶段显示错误与下一步动作。

## 入场与运动语言

首次进入 Sandbox 使用一次“场景开幕”转场：

1. 来源页面在约 180ms 内压暗，品牌导航保持稳定。
2. 黑色工作区从主画布区域展开，坐标网格与轴线从焦点位置建立。
3. 任务栏、状态轨道和代码面板分别以约 10--14px 的位移、60--90ms 的错峰进入。
4. 从首页提示词进入时，提示词在视觉和内容上延续到第一条任务，而不是重新闪现。
5. 完整开幕约 700--900ms，但主操作在前半段即可使用，动画不能阻塞输入。

完整开幕每次导航只播放一次。返回已有任务使用 180--250ms 的短恢复转场，不重复整套仪式。生成过程不使用永久漂浮粒子或循环炫光，只保留与真实状态绑定的线条、节点、计时与画布反馈。

`prefers-reduced-motion: reduce` 时取消空间位移、网格绘制和错峰，只保留 120--180ms 的透明度变化。低性能移动设备也减少模糊和大面积动画。

## 控件与人工接管

以下能力在所有端均必须可发现、可键盘操作并有明确禁用原因：

- 停止当前生成。
- 手动渲染当前代码。
- 手动调用 AI 修复，并允许用户补充修复说明。
- 直接编辑代码并保存为人工版本。
- 查看验证错误与完整渲染日志。
- 回退到任意已保存版本。
- 在低清预览成功后请求高清渲染。

自动流程运行时，用户可选择“停止并接管”；系统先停止后续阶段，再把最后一个完整版本交给编辑器，不能让后台结果随后覆盖人工修改。

## 多端适配

### Desktop（建议验证宽度 1440px）

- 保持主画布、可折叠任务栏和底部代码面板的工作室结构。
- 画布始终拥有最高面积和最高视觉优先级。
- 长日志、版本历史和代码编辑可以并排或叠层查看。

### Tablet（建议验证宽度 1024px 与 768px）

- 主画布仍为默认主体。
- 左侧任务栏收为可固定的侧滑层。
- 代码编辑器改为可调整高度的底部面板。
- 打开侧滑层时保留明显关闭方式、焦点约束和背景状态，不造成横向溢出。

### Mobile（建议验证 390 × 844）

- 不压缩成三栏。默认显示画布，并通过底部导航切换“任务 / 代码 / 预览”。
- 生成状态以紧凑阶段条覆盖在画布安全区，不遮挡主要预览。
- 主要操作的触控区域至少为 44 × 44 CSS px。
- 处理刘海屏、系统底栏、软键盘和长提示词；禁止页面级意外横向滚动。
- 代码编辑时避免软键盘把保存、渲染和退出操作完全遮住。

### Mobile landscape（建议验证 844 × 390）

- 画布与当前工具面板采用主次分屏，而不是沿用竖屏高度堆叠。
- 顶部品牌区压缩为必要操作，保证预览和停止按钮可见。

不同布局只改变呈现方式，不删减自动修复、手动渲染、手动 AI 修复、版本回退或日志能力。响应式验证必须同时确认浏览器报告的实际 CSS viewport，不能仅依赖截图工具声明的窗口尺寸。

## 错误处理

### AI 与检索

- 检索超时：使用经过验证的小型回退上下文，并在内部记录降级原因。
- 模型超时或限流：在安全范围内重试一次；仍失败则保留规划和已有草稿，允许用户重试。
- 非法或不完整输出：不进入渲染，先执行一次格式恢复；恢复失败计入自动修复次数。
- 用户取消：停止未开始的后续阶段，并尽可能取消当前请求；不删除已保存版本。

### 验证与渲染

- 语法或 API 预检失败：携带完整结构化诊断进入自动修复。
- 渲染失败：保留完整 traceback，界面默认展示摘要并允许展开技术详情。
- 渲染超时：终止对应子进程，标记超时阶段并允许降低复杂度后修复。
- 重复代码：命中基于内容和环境的缓存，不重新创建等价渲染任务。
- 自动修复两次仍失败：停止循环，清晰标记最后可运行版本或最后候选版本，交给用户手动修复。

### 客户端

- SSE 暂时断开：显示重连状态并从最后事件编号续接。
- 刷新：根据 `jobId` 恢复任务、版本和最后已知阶段。
- 后端重启：把未完成任务标记为中断但可重试，不永久停留在“生成中”。
- 预览媒体失败：画布显示可重试状态与代码，不显示空白黑屏。

## 可访问性

- 所有操作使用真实按钮、链接、标签页或对话框语义。
- 阶段变化通过可控的 live region 简洁宣布，不把每个流式 token 读给屏幕阅读器。
- 颜色不是唯一状态编码；同时使用文本、编号、图形和图标形状。
- 可见焦点在暗色背景、浅色面板和彩色状态上均达到可读对比度。
- 侧滑层、底部面板和错误详情具备合理焦点进入、返回和 Escape 行为。
- 视频预览提供播放/暂停与静音控制，自动播放遵循浏览器策略。
- 动画遵循 `prefers-reduced-motion`，并且不会阻塞点击、输入或导航。

## 性能与可靠性预算

- 提交后应立即收到 `accepted`；正常网络下首个阶段反馈目标在 1 秒内。
- 心跳只在没有新阶段事件的长任务中发送，避免高频 React 更新。
- 只在主画布运行持续动画；隐藏面板停止无意义动画。
- 代码流式更新节流批处理，避免每个 token 触发编辑器完整重排。
- 快速预览默认使用低清质量；高清渲染由用户在成功后主动触发。
- 相同代码、环境和质量复用渲染缓存。
- 自动修复严格限制两次，避免成本和等待无限增长。

这些是体验目标而非虚假进度承诺。界面显示实际阶段和时间，不根据预计耗时倒推百分比。

## 组件与模块边界

建议在实施计划中保持以下职责边界，最终文件名可按现有项目模式微调：

- `generation-orchestrator`：状态机、阶段推进、重试与取消策略。
- `generation-events`：事件类型、序列化和断线续接。
- `generation-job-store`：任务、事件序号和版本元数据。
- `scene-planner`：结构化场景规划与复杂度分类。
- `generation-context`：RAG 阈值、过滤、回退和上下文去重。
- `manim-validator`：语法、结构与已知 API 预检。
- `render-client`：低清/高清渲染、缓存键与完整诊断。
- `studio-shell`：响应式工作室布局与面板状态。
- `generation-status`：阶段轨道、计时、重连和错误摘要。
- `canvas-stage`：空闲、生成、渲染、预览和媒体错误状态。
- `version-history`：自动生成、自动修复和人工版本的选择与回退。

模块之间使用类型化输入输出，不共享隐式全局状态。现有 `use-chat`、Chat API 和 Sandbox 大组件应通过小步提取职责演进，避免在单个文件继续堆叠编排、网络、编辑器和布局逻辑。

## 测试策略

### 单元测试

- 新建/编辑/修复意图分类，尤其是默认示例代码不污染新建请求。
- 生成状态机合法与非法转移。
- 动态 token 预算和模型路由。
- RAG 相似度阈值、版本过滤、超时取消与回退。
- 上下文去重，保证当前代码只出现一次。
- 渲染缓存键稳定且不包含时间。
- 自动修复上限为两次。
- 事件序号、断线补发和取消后的结果隔离。

### 集成测试

- 使用可控的模型与渲染替身覆盖首次成功、语法失败后修复、渲染失败后修复、两次失败、超时、取消和断线重连。
- 验证每条路径都保存正确版本，并且人工修改不会被迟到的自动结果覆盖。
- 验证快速预览与高清渲染使用不同质量但共享正确的内容摘要。
- 验证 RAG 不可用时仍能生成，而不是卡在检索阶段。

### 渲染契约与真实样例

- 建立一组小型、可重复的 Manim 提示词：二维函数、几何构造、三维曲面、公式变换和参数动画。
- 在真实 Python/Manim 环境运行语法、场景发现和低清渲染冒烟测试。
- 对修复路径保留已知失败样例，验证错误信息足够让模型完成修复。
- 评估首次渲染成功率、自动修复恢复率、首次反馈时间、预览完成时间和用户取消率。

### 前端交互与可访问性

- 覆盖空闲、生成、验证、渲染、修复、完成、失败、取消和重连状态。
- 验证自动流程之外仍能手动渲染、手动 AI 修复、编辑、保存和回退。
- 使用键盘完成主要流程，并检查焦点、live region、对比度和减少动态效果。
- 验证长提示词、长错误日志、长代码、软键盘、媒体失败和慢网络。

### 多端端到端验证

至少在以下实际 CSS viewport 验证：

- Desktop：1440 × 900。
- Tablet landscape：1024 × 768。
- Tablet portrait：768 × 1024。
- Mobile portrait：390 × 844。
- Mobile landscape：844 × 390。

每个尺寸都要执行或恢复一条真实任务，检查无横向溢出、关键操作可见、面板可关闭、画布可用、代码可编辑以及手动能力未被隐藏。

## 交付验证门槛

实施完成前必须满足：

1. JavaScript/TypeScript 全量测试通过。
2. Python 渲染与相关测试通过。
3. TypeScript 类型检查退出码为 0。
4. ESLint 全量检查退出码为 0。
5. Next.js 生产构建退出码为 0，且无新增 hydration、无效 DOM、字体、媒体或路由警告。
6. 工作区现有会阻断以上命令的旧错误也被修复；不得把“非本次新增”作为完成豁免。
7. 启动真实开发环境并完整走通“提交 → 规划 → 生成 → 验证 → 快速渲染 → 自动修复 → 手动接管 → 刷新恢复”。
8. 桌面、平板、手机竖屏和手机横屏完成实际视觉与交互检查。
9. `prefers-reduced-motion` 下没有强制空间动画，所有主要操作仍可用。
10. 交付前检查 diff，确认没有覆盖或提交用户已有的无关改动。

若任何门槛因外部服务凭据或本地浏览器工具不可用而无法验证，交付状态必须明确标为未完成或被阻塞，不能声称已经全部通过。

## 实施顺序约束

实施计划应按可验证的纵向切片推进：

1. 先清理会阻断全量验收的现有类型、代码检查和构建错误。
2. 建立生成作业状态机、事件协议和版本模型。
3. 修正新建/编辑上下文并加入规划、模型路由和 RAG 质量门槛。
4. 加入语法/API 验证、稳定缓存、低清渲染和最多两次自动修复。
5. 重构 Studio Shell，并接入真实作业事件而非演示状态。
6. 完成沉浸式视觉、入场动效、多端布局与无障碍降级。
7. 补齐集成、真实渲染和多端端到端验收。

任何视觉状态必须连接真实后端事件后才算完成；任何自动化能力也必须保留对应的人工接管路径。

## 最终验收标准

1. 用户提交后立即得到真实任务反馈，长时间生成不会表现为页面卡死。
2. 每个任务按规划、检索、生成、验证、渲染和有限修复推进，阶段来源于真实状态。
3. 成功结果至少通过语法检查与一次低清真实渲染。
4. 自动修复不超过两次，失败后完整保留代码、日志和人工操作。
5. 手动渲染、手动 AI 修复、直接编辑、版本回退与高清渲染始终可用。
6. 相同代码在相同环境与质量下可命中缓存，不因时间戳重复渲染。
7. 新建请求不携带默认示例代码，模型上下文不存在重复或过期的当前代码。
8. 检索只注入相关且经过验证的示例；RAG 失败时可以安全降级。
9. Sandbox 具有明确的沉浸式暗场身份，与首页的黑、纸白、蓝、绿、橙数学语言一致，同时避免通用 AI 产品视觉。
10. 首次进入的开幕动效增强沉浸感但不阻塞操作，并完整支持减少动态效果。
11. Desktop、Tablet、Mobile portrait 和 Mobile landscape 均能完成完整创作与接管流程。
12. 全量测试、类型检查、代码检查和生产构建全部零错误，真实开发环境流程可正常运行。
